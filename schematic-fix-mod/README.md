# Create: Schematic Fix (`schematic_fix`)

Аддон для Create 6.0.10: схематичная пушка не «съедает» блоки и предметы. Dev-задача #196.

## Что было

- Перезапуск печати (кнопки «Стоп»/«Пуск», та же схема ещё раз) уничтожал часть уже построенных блоков и тратил на
  них предметы заново; если запаса не хватало, пушка вставала с «нет блока».
- Если на месте постройки стояла руда TFC/Firmalife или горелка всполоха, пушка списывала предметы и порох, а блок
  не ставила — предметы пропадали.

## Почему (по байткоду Create 6.0.10 и Create: Fast Schematic Cannon 1.4.1)

1. `SchematicPrinter.shouldPlaceBlock` считает блок готовым, только если состояние в мире **в точности** равно
   состоянию в схеме. Иначе, при режиме «заменять твёрдые блоки любыми» (по умолчанию), пушка ставит блок заново:
   `grabItemsFromAttachedInventories` списывает предмет, `BlockHelper.placeSchematicBlock` делает `setBlock` без дропа
   старого блока. Часть блоков после установки сама меняет свойство: мостки Create Deco
   (`createdeco:industrial_iron_catwalk`) тиком пересчитывают `bottom` по опоре снизу — в схемах из старой версии мода
   `bottom=true` без опоры. Такие блоки при каждом перезапуске перестраиваются и «съедаются».
2. Fast Schematic Cannon (`@Redirect` на `handleCurrentTarget` в `tickPrinter`) проверяет свой список
   `blocks_unbreak` (в сборке — все руды TFC и Firmalife, `create:blaze_burner`) уже после того, как `tickPrinter`
   списал предметы и порох.

## Что делает аддон

Миксин в начало `SchematicannonBlockEntity.shouldPlace` (по нему же пушка считает список материалов):

- в мире уже стоит блок того же вида, что в схеме (отличаются только свойства) — не ставить;
- в мире стоит блок из списка `blocks_unbreak` Fast Schematic Cannon (читается из его `Config` через reflection,
  без мода — пропускается) — не ставить.

Пушка идёт дальше, ничего не списав. Следствие: пушка больше не «чинит» повёрнутые не так блоки того же вида —
такой блок нужно сломать, тогда пушка поставит его по схеме.

Что аддон не меняет: блоки без своего предмета (кучи слитков, брёвен, угля, якорь верёвки и т. п.) пушка не ставит
и сама, даже с творческим ящиком; блок другого вида на месте постройки по-прежнему заменяется без дропа (так задумано
в Create, режим замены — в окне пушки).

## Кому ставить

Логика только на сервере. Ставить на сервер и хосту. Остальным игрокам не нужен, но и не мешает.

## Сборка и проверка

- `./libs.sh` (один раз), `./release.sh`.
- Проверка — на стенде всей сборки (MCP `pack_devserver` с `mods=[build/libs/schematic-fix-<версия>.jar]` и
  `overlay=check`): `check/kubejs/server_scripts/zz_cannon_test.js` — команды `/ct start`, `/ct status`. Нужны схемы
  `check/schematics/uploaded/Test/s1.nbt` («постройка») и `s4.nbt` (oil_facory) — MCP `schematic_get id=… save=…`.
  Площадка R: пушка печатает oil_facory из бочек (запас +10 %), потом та же схема ещё раз. Площадка O: «постройка»,
  в основании которой стоят блоки руды. В лог KubeJS — что не совпало со схемой и сколько предметов потрачено.

Результаты 2026-11-07 (схемы с сайта, вся сборка):

| | без аддона | с аддоном |
| --- | --- | --- |
| R, повторный запуск | ломает мостки, ставит заново, встаёт «нет блока» после 55 | потрачено 0, готово |
| O, руда под постройкой | потрачено 2784, на 310 клеток с рудой предметы пропали | потрачено 2476 (= 2784 − 308 клеток с рудой), лишнего 0 |

Ещё по этой задаче без аддона: 8 схем библиотеки с творческим ящиком и 1900s_workshop в выживании печатаются
полностью; расход совпал со схемой, сброс посреди печати лишнего не тратит.

Новая версия Create (зависимость `[6.0.10,6.1)`): сверить сигнатуру `SchematicannonBlockEntity.shouldPlace`.
