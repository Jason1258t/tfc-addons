# TFC Studio: Perf Fix (`perf_fix`)

Сборник исправлений производительности сервера по профилям spark группы (dev-задачи #267, #296). Каждое исправление —
миксин в чужой мод; если мода нет в сборке, его исправление просто не применяется.

## 1. Общие карты JourneyMap (JourneyMap Shared Maps 1.1.3)

**Что было.** По двум профилям spark от 06.11.2026 запись тайлов общей карты занимала 16% всего времени серверного
потока и треть времени тиков дольше 100 мс.

**Почему (по байткоду `RegionTileStore.writeTile`).** Каждый тайл, присланный игроком, мод сразу пишет на диск в главном
потоке сервера:

- читает **весь** файл региона `r.X.Z.jmregion` (`Files.readAllBytes`), хотя нужен только заголовок 8200 байт;
- открывает файл четыре раза (проверка, размер, дописывание, заголовок) — на Windows это `CreateFile`, 11–25% времени
  потока в профилях;
- файл между остановками сервера только растёт: новая версия тайла дописывается в конец, а пересобирается файл только
  при остановке (`ServerTileCache.save` на `ServerStoppingEvent`). Чем дольше сессия, тем дороже каждый тайл.

**Что делает аддон.** Запись тайла уходит в один фоновый поток. Тайл к этому моменту уже лежит в памяти мода и
пересылается другим игрокам как раньше. Формат файла тот же: файл открывается один раз, читается только заголовок,
запись дописывается в конец, в заголовке меняется одна ячейка. Поток берёт тот же замок файла, что и пересборка файла при
остановке. При остановке сервера (у хоста — выход в меню) аддон ждёт, пока очередь допишется (до 30 с).

## 2. Октопотеутис TFC (TFC 4.2.9)

**Что было.** В первом профиле исчезновение октопотеутисов занимало 3,2% времени: сервер синхронно грузил чанк.

**Почему (по байткоду `IGlow.tryRemoveLight`, `Octopoteuthis.remove`).** Светящееся существо ставит рядом с собой блок
света и запоминает его позицию. При исчезновении TFC проверяет, загружен ли чанк **самого существа**, а блок читает по
запомненной позиции. Она бывает далеко или равна (0,0,0) — тогда сервер ждёт загрузки того чанка.

**Что делает аддон.** Проверяет чанк блока света. Если он не загружен или свет ещё не ставился, блок не трогается: блок
света TFC сам исчезает на случайном тике (`TFCLightBlock.randomTick`, 1 из 20).

## Проверка

`./test-server.sh` — сервер разработки с JourneyMap Shared Maps, TFC и Patchouli из jar сборки, по два запуска без аддона
(`-Dperf_fix.jmsharedmaps.disabled=true -Dperf_fix.glow.disabled=true`) и с ним:

- `/pftest bench 400 5` — 2000 тайлов по 4–8 КБ через сам мод (`ServerTileCache.putIfNewer`, как при приходе от
  игрока) в главном потоке, время;
- `/pftest verify` — файлы регионов читаются кодом мода (`RegionTileStore.loadRegion`) и сравниваются с памятью мода;
  после перезапуска — ещё раз, мод заново читает свои файлы;
- `/pftest glow near|far` — октопотеутис с блоком света рядом (свет должен сняться) и в незагруженном чанке (чанк не
  должен загрузиться).

Отключить исправления на живом сервере — те же ключи `-D…disabled=true` в параметрах Java.
