# Stress Test — нагрузочные прогоны сборки (только для разработки)

Мод для клиентского стенда (`npm run client-stand` в tfc-plans): по плану `stress-plan.txt` в папке игры строит
нагрузку и пишет в лог строки `[STRESS]` — TPS, MSPT (медиана, p95, p99, максимум), чанки, сущности, куча, GC, FPS.
Без `addon.json`: на сайт и в сборку не попадает.

Запуск: `./libs.sh && ./gradlew build`, затем `./run.sh <план> --ram --no-pack [--mod <другой jar>]` — план из
`plans/` (`fly`, `plant`, `scale`, `combo`, `memory`), длительность — строка `# settle:` плана.

Шаги плана: `wait <с>`, `mark <имя>` (новый отрезок замера), `cmd <команда>`, `fly <чанков> <блоков/тик> [y]`, `end`.
Команды: `/stress plant [копий]` — электростанция (котёл 3×3×5 на 9 горелках, 9 паровых двигателей, ротор и
трёхфазные щётки EE, помпы от батареи 600 В, моторы с нагрузкой Create, нагреватели и лампы, IE через конвертеры,
освещение IE по двухжильному кабелю); `/stress report`; `/stress pigs <n>` — загон свиней TFC; `/stress fly`;
`/stress mark`; `/stress heap <метка>` — полная сборка через гистограмму живых объектов: живой объём кучи, верх
классов, счётчики миров и чанков (утечки), память вне кучи (Metaspace, буферы, RSS и своп процесса), паузы сборщика с
причинами с прошлого замера. Каждая пауза сборщика от 200 мс — строкой `[STRESS] GC` сразу, флаги JVM — при запуске.
