# EE Extras (`ee_extras`)

Аддон сборки для Create Electro Energetics (до 2.0 — «EE Rectifiers», `ee_rectifier`; старые блоки переходят на
новые id по псевдонимам). Общие правила разработки аддонов — [docs/addons.md](../../docs/addons.md); для игроков —
сайт, «Справочник → Аддоны».

ставятся выводом кабеля от игрока (на стене — вверх), ключ по лицевой грани — следующее из четырёх положений (у EE —
только крен, два из четырёх); соединитель EE с подключёнными проводами ключ не поворачивает (номера его узлов зависят от
положения — провода бы оборвались). Нужен на сервере и у
всех игроков. NeoForge 21.1.219+, Create 6.0.10, Electro Energetics 1.1.2+.

## Провода ЛЭП (2.1)

С версии 2.10.2 провис стального ПС уменьшен втрое (sag = 0,4 / 3),
многопроволочного медного М — на 40% (sag = 0,6). Изменение действует и с натяжным зажимом,
в том числе на существующие линии после перезапуска. Пролёт, сопротивление и допустимый ток сохранены.
Линейная зависимость от sag подтверждена по WireData.getSag(double) из Electro Energetics 1.1.2.
На сервере разработки: 24/24 проверки длины и натяжения; ПС на пролёте около 60 блоков — 0,40 блока без зажима, 0,08 с зажимом. Электрические измерения совпали с расчётом. Вид линий на клиенте не проверен.

`lines/LineWire` — семь типов проводов EE (те же клеммы и изоляторы): медная шина, силовой кабель, М, АС, А, бронзовый,
ПС; числа и их смысл — в комментарии класса и на сайте. В EE нагрев зависит только от тока (предельный ток =
33,3 + предельная температура / 30), сопротивление — только потери, провис середины = 0,05 · sag · пролёт · f.
`lines/Tension` — натяжной зажим (навесная деталь EE + действие по клику на провод): натягивает провод до предела
материала (f = 0,2…0,6, длина = пролёт − (1 − f)); раз в 2 с проверка возвращает провода ЛЭП к допустимой длине (без
зажима — не короче пролёта). Железному проводу EE провис 1 → 0,6 (отражением, поле final). `lines/LinesClient` —
подсказки катушек (характеристики — механизмом EE через реестр подсказок Create). Графика и рецепты — `art/lines.py`.

## Поверхностный провод (2.16, dev #205)

Пакет `wire/` — перенос поверхностного провода Create: Power Grid 0.6.2 (Apache-2.0, `NOTICE`; в каждом классе — откуда и
что изменено). `SurfaceWireEntity` — кусок провода (позиция + отрезки `Point` по сетке 1/16), `WireEnd` — концы
(прибор `CableEnd` вида DUPLEX, узел ответвления, край провода, точка на поверхности, будущий узел), `BlockTrace` —
поиск пути (A*), `SurfaceWireItem` — прокладка, `WirePackets` — синхронизация, ответвление, резка, `JunctionData` — узлы
ответвлений: по FIXED-узлу EE без блока на жилу (`createDetachedNode`, EE 1.1.2). Кусок с двумя подключёнными концами
— две жилы EE длиной маршрута. Своя проверка опоры (в Power Grid её нет). Распределительная коробка `JunctionBoxBlock`
(как изолятор). Тонкий изолированный провод — `cable/ThinSpoolItem`, оболочка `CableWires.THIN`, между двумя
изоляторами не тянется. Настройки: `ee_extras-server.toml`, `surface_wire`. Проверка: `/wiretest build|power|report|
cut|unbranch|wall|breakb|long|lantern|thin|thinreport` на сервере (`IE=1` для фонаря), `WIRE=1 ./test-client.sh`.

## Устройство

- `lantern/` (2.4) — фонарь IE в сети EE. `LanternConversion` (из `CableEvents`): клик катушкой двухпроводного кабеля
  по электрическому фонарю IE ставит `LanternBlock` в том же положении (IE facing=down — стоит, у нас FACING вверх;
  up — висит) и пускает клик в прокладку; с проводами IE — отказ (`IeWires`, API IE 12.4.2, классы IE грузятся только
  при фонаре IE в мире). Для кабеля — как изолятор: все узлы в гнезде провода IE ({8, 1, 8} лицом вверх, как
  `ElectricLanternBlockEntity.getConnectionOffset`), кабели жила к жиле. `LanternDevice` — резистор 1000 Ом, горит от
  50 В и ещё 40 тиков после (переменный ток проходит через ноль), `SpawnPreventingDevice` EE. Модели — фонаря IE по
  ссылке (`art/cables.py`, `lantern_blockstate`), выпадает фонарь IE, своего предмета нет; подсказка — на фонаре IE.
- `lantern/EeFloodlight*`, `FloodlightDevice` (2.7) — прожектор IE в сети EE. Наследник `FloodlightBlock` IE, а не `CableEndBlock`: `FloodlightBlockEntity` читает `IEProperties.FACING_ALL`, а `FACING` у блоков EE — другой объект с тем же именем, два в одном блоке нельзя (IE 12.4.2, EE 1.1.2, по байткоду). Блок-сущность — сама IE, свой блок добавлен в тип `FLOODLIGHT` через `BlockEntityTypeAddBlocksEvent`; для кабеля блок — `cable/CableJunction`. Регистрация только при IE. Устройство держит запас прожектора полным, пока есть напряжение, и даёт 440 Ом, только когда он светит.
- `converter/CableConverter*` (2.7) — кабельный преобразователь: формулы половины «заряд» `BidiConverterDevice`, вход — жилы кабеля, FE — в блок за задней гранью. Проверка: `IE=1 ./test-server.sh 'rectest floods' …` (`Flood`), настоящий клиент — `./test-client.sh` (`ClientTest`), снимки в `run/screenshots`.
- `EeExtras` — регистрация (блоки, предметы, устройства EE, типы проводов, блок-сущность), псевдонимы `ee_rectifier:*`,
  вкладка творческого режима EE. `Layout` — раскладки клемм (выпрямители, преобразователь, соединитель).
- Выпрямители и инверторы — `PowerBlock` (до 2.2 — `RectifierBlock`), `RectifierDevice` (с 1.1 без диодов: резисторы
  входа, сопротивление пересчитывается каждый тик, выход — `energyLimitedSource` с запасом; подробности — комментарий в
  классе), `InverterDevice`. Ступени — `Tier` (лёгкий 6 кВт / тяжёлый 48 кВт, высота клемм; id тяжёлого — `heavy_` +
  id лёгкого). Нагрев (2.2) — `Heat`, формулы вариака EE 1.1.2 (по байткоду `VariacDevice.postTick`): тепло =
  мощность × 1300 / (номинал / 0,75), `ElectricalDevice.updateTemp` и `handleTemp` (дым 30 000, сгорание 40 000, в
  масле 60 000 / 80 000; только при `componentDamage`). Температура — `Temp` в `/cee device_data`.
- Инвертор (2.2, такт сети переделан в 2.5.1): вход — резистор (напряжение — среднее по микротикам со знаком), выход —
  `ac/Sine` на каждой паре фаз (у трёхфазного — треугольником), ЭДС = (π/3) × U пост. линейная (однофазный — (π/2)),
  внутреннее сопротивление — «10 % на номинал», не меньше ограничения запасом, как у `energyLimitedSource`. Такт — как
  у преобразователя частоты: `ac/Meter` по мгновенным напряжениям микротиков (в сборке microTicks = 8), режимы `off`
  (замер), `grid` (своя ЭДС выше сетевой; угол `predict(0)` и шаг — из замера, трёхфазный идёт за любым порядком фаз),
  `island` (своя синусоида 1 Гц, у трёхфазного порядок фаз генераторов EE — шаг < 0); сглаженная отдача < 0 — `off`.
  До 2.5.1 замер шёл по `getVoltageAt`, который при microTicks > 1 отдаёт действующее без знака, — в сборке инвертор
  к сети не подстраивался. В `/cee device_data` — `Mode`, `Amplitude`, `GridHz`, `PhaseError`.
- `ac/` — переменный ток (2.5): `Meter` — вектор стороны (амплитуда, угол, шаг за микротик) по мгновенным напряжениям
  микротиков (в сборке microTicks = 8, `getVoltageAt` там — действующее), `Sine` — источник синусоиды за
  сопротивлением на каждом микротике (как обмотки генератора EE), `FrequencyConverterDevice` (режимы no_input / wait /
  foreign / island / grid, звено с запасом как у инвертора), `SynchronizerDevice` (авто-включение, подгонка красным
  сигналом, защита), `AcBlock`/`SynchronizerBlock` (окно значения, сигнал — грань «быстрее» из положений клемм EE),
  `TallBaseBlock` + `TallBlockItem` (промышленный шкаф: устройство в верхнем блоке), `Cooling` (радиаторы, как у
  трансформатора EE), `AcBlocks` (регистрация). Модели — `art/acmachines.py`. Подробности EE — docs/addons.md,
  «Переменный ток EE».
- `generator/` — компактный генератор (2.3). Блок кинетический, как щёточный узел EE (`DirectionalKineticElectricBlock`,
  вал — только в задней грани), плюс крен, вода и масло, как у плит EE. Числа — от генератора EE 1.1.2 (по байткоду:
  выработка 48 × магниты × об/мин Вт, нагрузка на вал 48 × (магниты + 0,125) SU на 1 об/мин, ЭДС = выработка / 100 А):
  8 SU на 1 об/мин (`BlockStressValues.IMPACTS`), 6 Вт и 0,5 В на 1 об/мин, номинал нагрева 1,2 кВт. Устройство
  `GeneratorDevice` — как `GeneratingDevice` EE (запас ≤ 10 тиков мощности, `energyLimitedSource`); приток каждый тик
  ставит блок-сущность (неизрасходованное пропадает, как у EE). Полувал на клиенте — `GeneratorClient`
  (`OrientedRotatingVisual` / `KineticBlockEntityRenderer` с `SHAFT_HALF`, смотрит назад).
- `converter/` — двусторонний преобразователь. Формулы — как у `ConverterDevice` EE 1.1.2 (по байткоду): заряд — резистор
  max(20 Ом, U² / свободное место в запасе), разряд — `energyLimitedSource` с запасом, оба запаса до
  `converterMaxPowerKw`, перевод `wattFeTConversionRate`. FE: сначала через грань, которой касается сосед, потом
  через любую его грань, которая принимает (для заряда) или отдаёт (для разряда) — у конденсатора IE грань либо вход,
  либо выход. Сам блок тоже отдаёт возможность FE через заднюю грань (грань-выход конденсатора кладёт в разряд).
- `cable/CableCap` (2.15, dev #273) — крышка двухжильного кабеля на любой прибор EE ровно с двумя контактами: модификатор
  прибора, а не блок (по решению хоста) — в мире хранится список приборов с крышкой (`ee_extras_cable_caps`). Подходит
  ли прибор — по коду EE 1.1.2: `ElectricalDeviceBlock.getNodePositions` + `isNodeAccessible`, ровно два узла
  (соединители кабеля — `BundledWireTerminationBlock`, `CableJunction` — не приборы); контакт 1 — меньший номер узла.
  Для кабеля прибор с крышкой — `CableEnd` с `contacts`: жилы — на контакты, оболочка — на отдельную пару контактов между крышками (свой узел у
  чужого блока не завести: EE каждый тик сверяет узлы с `getNodePositions`). Отказы: не прибор, не два контакта, на
  контактах провода, крышка уже есть; кабель на прибор без крышки — подсказка; провод EE на контакты под крышкой —
  отказ. Shift + пустая рука — снять (крышка и катушки кабелей — игроку). Сверка раз в 10 тиков: прибора нет — крышка
  выпадает на его месте, провода EE снял вместе с узлами. Клики — обработчик HIGH: у вольтметра EE клик по окну
  значения иначе забирает Create (`ValueSettingsInputHandler`). Проверка: `./test-server.sh 'forceload add 0 140 20 160'
'rectest caps' 'sleep 4' 'rectest capreport' 'rectest captake' 'rectest capbreak' 'rectest capreport'` (`CapTest`),
  сохранение — `KEEP=1` и снова `capreport`.
- С 2.18 (dev #276) крышка накрывает оба контакта с запасом по краям. При загрузке чанка и при установке, снятии
  или поломке клиент получает список крышек в чанке. Катушка показывает название крышки при наведении.
  Оболочки двухжильного кабеля и тонкого провода отображаются от ввода крышки через два клиентских перехвата
  координат EE 1.1.2 (Flywheel и обычный рендерер); при смене версии EE нужно проверить оба пути. Сетевые узлы
  и формат сохранения прежние. Поверхностный провод по поверхности использует тот же ввод при прокладке.
  Клиентская проверка и снимки — `CAP=1 ./test-client.sh`.
- С 2.18.1 (dev #283) между крышками оболочка идёт по паре контактов 1–2, а жилы по-прежнему идут 1–1 и 2–2.
  EE 1.1.2 хранит только одно соединение на пару узлов, поэтому раньше первая жила перезаписывала оболочку.
  Старый кабель с двумя целыми жилами получает обычную двухжильную оболочку при сверке мира. Прежний тип
  оболочки после перезаписи восстановить невозможно. Серверная проверка — `rectest caps` и `rectest capreport`.
- `cable/` — кабели. В EE 1.1.2 катушка двухпроводного кабеля второй клик не обрабатывает; прокладку делает
  `CableLaying` (через `PlayerInteractEvent` для катушки EE и в `useOn` своей катушки). Кабель — оболочка (декоративный
  провод EE) и невидимые жилы; `CableData` следит, чтобы кабель не остался без части. Положения соединителей — `CableOrientation`
  (ROLL + 2·FLIP), подсветка и подпись вывода кабеля с катушкой в руке — `CableHud` (клиент). Подробности —
  [docs/addons.md](../../docs/addons.md), «Кабели EE».
- `mixin/BundledWirePreviewMixin` (клиент, 2.1.1) — исправление EE 1.1.2: предпросмотр кабеля (`BundledWireApplyingBehaviour.tick`)
  при выбранном первом конце и прицеле не на узел кабеля строил соединение с узлом null — вылет игры, если рядом
  есть хоть один провод. Узел под прицелом подменяется выбранным (соединения с собой не бывает). Мягкий, как и второй.
- Вкладка EE: аддон докладывает то, чего EE 1.1.2 туда не кладёт (двухпроводной соединитель и катушка; синхроскоп,
  частотомер, трёхфазные щётки — без `showACContent`), иначе их нет в JEI и поиске творческого режима.
- `mixin/WirePointsRawMixin` (2.3.3) — настоящая причина веера у гирлянды подвесных изоляторов: в EE 1.1.2
  `QuadraticWireHelper.wirePointsRaw` дописывает точки в буфер провода, не очистив его, и Flywheel рисует все прошлые
  положения качающейся гирлянды. Миксин очищает буфер в начале метода. Команда `/eeextras wires` (`WireDiag`, клиент) —
  замер проводов EE, отрисовок и кусков Flywheel; ею причина и найдена.
- `mixin/WireVisualMixin` (клиент, переделан в 2.1.2) — исправление EE 1.1.2: отрисовку провода
  (`WireVisual.recreateInstances`) Flywheel зовёт из кадра и из обновления света в разных потоках одновременно, отрезки
  теряются из списка и остаются в мире «застывшими» (веер у качающейся гирлянды подвесных изоляторов до перезахода).
  Миксин пускает к проводу по одному потоку (обёрнуты `beginFrame`, `updateLight`, `delete` — без клиентских классов в
  сигнатуре, поэтому применение видно и на сервере разработки), запоминает все созданные проводом отрезки и удаляет
  те, что выпали из его списков. Мягкий: не применится — игра не падает; итог пишет в лог клиента `WireFixCheck`
  («исправление отрисовки проводов EE применено / НЕ применено»). В 2.1.0–2.1.1 был вариант с обёрткой
  `recreateInstances` — в игре веер остался, применился ли он, неизвестно (лога не было).
- `art/gen_assets.py` + `art/cables.py` — текстуры, модели (тяжёлые — `heavy_model`: корпус, рёбра-радиаторы по сторонам
  без клемм, проходные изоляторы с шапками; текстура — верх лёгкой + `heavy_parts`), блокстейты (изоляторы и катушка — перекраска текстур EE
  из jar сборки — кеш снимка, `npm run pack:fetch`). Иконки для сайта рисует общий генератор `scripts/mcp/render.mjs` (его вызывает `release.sh`).

## Платы L1 (dev #22, M4)

`pcb/PcbItems` регистрирует предметы `l1_board_blank`, `l1_mask`, `l1_board` и data component
`ee_extras:pcb_topology` (`CompoundTag`). Маска хранит топологию; травильная ванна Destroy Extras переносит её на плату
через `ItemStack.transmuteCopy`, поэтому содержимое не ограничивается фиксированным JSON-рецептом. С версии 2.6.0
заготовка прессуется из фибровой плиты IE и медной пластины, маска крафтится из бумаги и чёрного красителя. Это первый
Survival-вариант L1; редактор топологий и следующие уровни плат относятся к последующим этапам. На dedicated server
предметы L1 прошли цикл травления, точное сравнение топологии, перезапуск и разрушение/повторную установку ванны.

## Промышленные платы L2/L3 (dev #22, M11)

Фотолитограф `pcb_photolithographer` принимает заготовку, многоразовый проверенный `pcb_design` и фоторезист. После
травления в Destroy Extras установка `pcb_via_metallizer` расходует медную фольгу, металлизирует переходы и собирает
готовую плату. Обе машины автоматизируются item handler без нового GUI; состояние видно через очки инженера. Тип
`ee_extras:pcb_process` задаёт операцию, уровень, напряжение, ток и время в JSON: L2 — 240 В / 4 А, L3 — 600 В / 8 А.
Прогресс останавливается при просадке питания или заполненном выходе, входы расходуются только вместе с готовым
результатом. Все промежуточные предметы и плата получают точную копию `PCB_TOPOLOGY`, включая via и все слои.

Survival-рецепты находятся в сайт-датапаке «EE Extras — промышленные платы M11»: четыре операции машин, два варианта
травления, фоторезист из фенольной смолы и этанола, а также крафты обеих машин. Старый маршрут L1 не изменяется.

## ComputerCraft и CCBR (dev #22, M12)

`pcb/PcbItems` регистрирует 30 компонентов для компьютеров, карманных компьютеров, черепах и периферии CC, а также
магнитный носитель дискеты. `art/cc_modules.py` формирует модели и 69 записей сайт-датапака M12: 30 рецептов компонентов,
35 замен CC, две замены CCBR, отключение дублирующего прессования CCBR и общий тег изоляции. Аудит охватывает все
75 исходных рецептов CC: 35 изменены, 40 сознательно сохранены. Платы L1/L2/L3 и микросхемы CCBR образуют производственную
цепочку; механические сборки выполняются в Create, пайка — в More Red.

ID устройств и микросхем, Lua/API, старые мировые данные и TFC-инструменты черепах не меняются. Transform-рецепты
сохраняют data components компьютера при сборке и улучшении. `DiskRecipeMixin` подменяет только носитель в штатном
рецепте дискеты, сохраняя её ID, окраску и данные. `UpgradeManagerMixin` нормализует prototype эталонного стека CC для
стандартной проверки периферии: TFC уменьшает общий размер стека до 32, а эталон CC остаётся со старым размером 64.
Переопределённые проверки, включая инструменты черепах, вызываются штатно.

Проверка: `CC=1 TFC=1 IE=1 ./test-server.sh 'rectest cc'`; повтор с `KEEP=1` проверяет восстановление мира.
Датапаки M10 `Nh1ATmqCY92Hao48hOAQ`, M11 `cbH7wTaHOr5vQMs4Usgb` и M12 `tcegd3kspq62oHuM3YmF` включены для
установки через `tfc pull` (dev #224). Вместе с M6 они покрывают все 54 новых материала и компонента электроники:
17 рецептов M10, 7 рецептов M11 и 30 рецептов M12; `pcb_design` создаётся в столе чертежей, а не отдельным крафтом.

### Динамик, мотор, аккумулятор и принтер (dev #248)

Деплойер Create намагничивает стальной стержень катушкой, которая остаётся в руке деплойера. Нагретый пресс
формует диффузор из бумаги и воды. Магнит используется в динамике и малом моторе. Актуатор получает магнит в составе
мотора, а для его крышки используется ABS.

Свинцовый аккумулятор собирается из свинцовых пластин, электролита, разделителя из PET-плёнки и корпуса из ABS.
Для электролита нужна серная кислота из штатного контактного процесса Destroy. Разбавьте её водой до 4–5 моль/л
и разлейте раствор через наполнитель Create по 125 мБ в бутылочку. Чернильный картридж для печатающего механизма
собирается из чернильного мешка, ABS-корпуса и PET-уплотнения. Рецепты входят в M12.

### Антенны, карманный экран и CC:C Bridge (dev #249, #259)

Деплойер Create наматывает медную проволоку на стальной стержень. Антенна ставится в сетевой
приёмопередатчик, который целиком входит в эндер-приёмопередатчик. Цветная матрица для продвинутого карманного
компьютера собирается из стекла, ABS, RGB-люминофора, продвинутого драйвера и разъёма. Она нужна для прямой
сборки и улучшения. RedRouter, Animatronic, Scroller и Source Block собираются из модулей EE Extras.
Преобразование Source ↔ Target остаётся 1:1. Предметный тег изоляции принимает ABS, пластмассовые листы
и полимеры для сетевого кабеля и отсека хранения.

## Питание CC: Tweaked (2.12)

**Стационарный ПК.** Поставьте двухжильный ввод питания вплотную к компьютеру, щёлкнув по любой его грани, и
подключите катушкой двухжильный кабель. Рассчитан на 300 В переменного (действующее значение) или постоянного тока.
Допустимо 240–330 В на входе. Это напряжение до преобразования внутри блока питания. Номинальная нагрузка обычного
ПК — 80 Вт, продвинутого — 180 Вт, выключенного ввода — 2 Вт. При попытке запуска ввод до двух секунд проверяет
напряжение под нагрузкой. При обрыве или просадке компьютер выключается, файлы сохраняются. После восстановления
питания включите его снова. Уже установленные компьютеры подключаются так же. Щелчок пустой рукой по вводу
показывает напряжение.

**Перенапряжение.** Выше 330 В ПК выключается. Устойчивое напряжение выше 390 В выводит ввод или станцию из строя
при включённых повреждениях компонентов EE. Дым и сообщение на вводе указывают на аварию. Замените блок после
устранения причины. Если на момент пробоя действующее напряжение достигло 500 В, подключённый ПК разрушается.
Мир сохраняет каталог файлов прежнего ID, но новый ПК получит свой ID.

**Карманный ПК.** Вставьте его в зарядную станцию правой кнопкой, заберите пустой рукой. Щелчок пустой рукой
с зажатым Shift показывает заряд и напряжение. Заряд также виден в подсказке карманного ПК. Станция берёт до
40 Вт при 300 В и передаёт 85% измеренной энергии аккумулятору. Ёмкость — 18 Вт·ч, расход — 3 Вт у обычного
и 6 Вт у продвинутого. Новые и старые карманные ПК начинают с пустой батареей. Данные устройства сохраняются
при разряде и зарядке.

Ввод и станция используют узлы 1 и 2 `BundledWireTerminationDevice` из EE 1.1.2. Мощность нагрузки считается как
`U² / R`. Номиналы выбраны по классу блоков питания реальных компактных ПК с учётом потерь на входе и игровой
ступени сети. [Матрица блоков питания ThinkCentre M90q](https://psrefstuff.lenovo.com/syspool/ThinkCentre%20M90q%20Gen%203%20Adapter%20Matrix.pdf)

В CC 1.120.2 запуск и восстановление после загрузки идут через `ServerComputer.turnOn`, а расход аккумулятора
привязан к `PocketComputerItem.tick`. Заряд хранится на предмете, содержимое станции и состояние её входа — в
сохранении устройств EE.

## Рабочие платы EE (2.19.0, dev #280)

На столе проектирования выберите уровень L1–L3 и инструмент в палитре. Проложите дорожки и расставьте выводы
на любых свободных ячейках вдоль края первого слоя. На установленной плате контакты находятся в тех же ячейках.
«Контур» удаляет материал ячейки вместе с дорожками и деталями всех слоёв. Повторный клик восстанавливает
материал ячейки. Тип детали, направление, сопротивление и порог выбираются справа. Номиналы задаются готовыми
значениями, ёмкость задаётся в мФ, предохранитель и амперметр используют порог в амперах. Соседние дорожки
подключаются вдоль стрелки, у реле и транзистора управляющая пара находится поперёк неё. У реле ПКМ по кнопке
направления переключает нормально разомкнутый и нормально замкнутый контакт.

Положите бумагу, чтобы сохранить чертёж. Для сборки оставьте ячейку стола пустой и нажмите «Собрать».
Стол возьмёт из инвентаря одну чистую плату уровня проекта и детали. Чистую плату можно положить и в стол.
Для подключения тонкой катушкой сначала нажмите на контакт платы, затем на второй контакт платы или прибора EE.
Старые собранные платы сохраняют прежнюю нумерацию клемм и подключения.
На собранной плате ПКМ пустой рукой замыкает кнопки на секунду,
Shift + ПКМ переключает фиксируемые контакты. Редстоун-вход с севера, выход на запад. Измерители выдают 0–15
пропорционально заданному пределу, а первое показание можно вывести через передатчик дисплея Create.
Старые платы и чертежи остаются материалами для существующих рецептов. Снятая рабочая плата сохраняет схему,
включая перегоревшие предохранители. Конденсаторы при снятии платы разряжаются.

| Уровень | Напряжение | Рассеиваемая мощность | Ток ветви |
| ------- | ---------: | --------------------: | --------: |
| L1      |       48 В |                 12 Вт |     0,5 А |
| L2      |      128 В |                 48 Вт |       1 А |
| L3      |      230 В |                120 Вт |       2 А |

48 В — шина солнечной панели, 128 В — верхний диапазон компактного генератора, 230 В — номинал приборов
освещения EE. Бюджет L1 выдерживает нагрузку 220 Ом на 48 В (10,5 Вт), L2 — 470 Ом на 128 В (34,9 Вт),
а L3 — 470 Ом на 230 В (112,6 Вт, близко к прожектору EE на 120 Вт). Ток и мощность — игровые пределы
для плат управления с возрастающим запасом по меди и теплоотводу. Мощность относится к потерям внутри платы. Предельный ток отдельно защищает дорожки,
которые пропускают ток с малыми потерями. Для переменного тока применяются действующие значения за тик.
Перенапряжение сжигает плату сразу. При перегрузке накапливается превышение относительной мощности или квадрата
относительного тока. При двукратной мощности плата выдерживает около двух секунд при 20 TPS, при меньшей нагрузке
нагрев спадает. Сгоревшая плата отключает цепь и выходы. Снимите её и нажмите «Разобрать» на столе проектирования.
Для каждого установленного компонента отдельно проверяется шанс возврата: 70% для кнопок, переключателей и
разъёмов, 45% для транзисторов, диодов и индикаторов, 60% для остальных деталей. Уже сгоревший предохранитель
не восстанавливается. Если ни одна попытка не удалась, с вероятностью 85% спасается одна случайная деталь
из числа установленных и пригодных к разборке. Даже у платы с одной деталью вероятность пустого результата
не выше 8,25%, если эта деталь ещё подлежит возврату.

EE 1.1.2: `BridgeCollector.Builder` включает ветви платы в общую матрицу EE. Из-за единственной записи
`CircuitBuilder.connect` на пару узлов ветви разделены внутренними узлами, включая параллельные детали.
Конденсатор и диод используют `CapacitorProperties` и `DiodeProperties` из EE. Измерения берутся из
`SimulationResults`, а переключение контактов и изменение мира происходят после расчёта.
Плата имеет до 60 мест для контактов по периметру и до 64 ветвей схемы, кроме служебных узлов решателя.

Стенды сервера разработки: `pcbcircuit editor` — сборка, установка и снятие L1–L3, контур, шесть контактов и тонкий провод, `rectest pcb` — старые
чертежи, `pcbcircuit advanced` — резерв, диод, таймер, предохранитель, измерители и транзистор,
`pcbcircuit salvage` — выходы утилизации, `pcbcircuit stress` — платы на предельном размере.

### Модульные платы — текущая разработка #301

Ветка `feat/pcb-modules`, ещё не выпуск. Монтажная сетка остаётся 16×16; корпус может занимать несколько
ячеек. Кнопка — 2×2, переключатель — 2×3, реостат — 2×4, ползунок — 2×5, механический таймер — 3×3, клок — 2×2.

Размеры, модели, выводы и минимальный тир описаны общим каталогом `PcbModules`.
Слой 1 — монтажная сторона и видимые дорожки; остальные слои предназначены для внутренних трасс и переходов.

В редакторе рисуются модели деталей, а не предметы-заменители. Выбор, перенос и удаление работают по всей площади
корпуса. ПКМ выбирает существующий модуль для настройки; недопустимые пересечения и выход за край отклоняются

изначально изолированы; общий провод при необходимости задаётся явно. Разрывы сохраняются вместе с чертежом.

Реостат имеет два вывода, ползунок — два конца дорожки и движок W. Номинал задаётся при проектировании,

Выгруженная плата не выдаёт очередь пропущенных импульсов; после загрузки механический таймер учитывает
прошедшее игровое время, клок продолжает фазу по игровым тикам. Обратной совместимости старых проектов нет:
редактор предлагает очистить старый формат и создать схему заново.

### Прототип: стабилизатор питания L2 (без выпуска, #301.16)

Модуль `pcb_voltage_regulator`, 3×3, выводы Вх+/Вх−/Вых+/Вых−. Общая земля соединена внутри через 0,01 Ом;
при общей внешней дорожке дополнительное сопротивление не добавляется. Вход 8–12 В **постоянного** тока,

Это параметрическая схема: вход → балласт 150 Ом → выход, шунтирующий стабилитрон между выходом и землёй.
Шунт соединён с выходом через измерительные 0,01 Ом. Все внутренние ветви имеют собственные промежуточные узлы:
`CircuitBuilder.connect` в EE заменяет повторное ребро между той же парой узлов, поэтому прямое параллельное
подключение к дорожкам питания регистра недопустимо. Его пассивная ВАХ: выше 5 В ток `(U−5)/0,2`, ниже −0,7 В ток `(U+0,7)/0,2`, в промежутке утечка `U/1e9`.
EE 1.1.2 (`DiodeProperties.tick/afterTick`, проверено из установленного jar) допускает такой штамп сопротивления
и эквивалентного тока. Ограниченная итерация сети решает ВАХ в текущем отсчёте, без повторного шага конденсатора.
Независимого источника энергии в модуле нет. На холостом ходу он продолжает потреблять ток через балласт и шунт.

При малом входном напряжении или нагрузке свыше допустимой выход плавно проседает. КЗ ограничено балластом:
при 12 В теоретический максимум 80 мА, потери до 0,96 Вт. Избыточное напряжение не является рабочим режимом.
Потери балласта, возврата и шунта рассчитываются по каждому реальному отсчёту EE и один раз входят в тепло платы.
Локальная тепловая модель: 2 Дж/К, 0,02 Вт/К к среде 20°C; вход размыкается при 90°C, возвращается при 60°C.
Температура и состояние отключения сохраняются; отключение не заряжает выход и не добавляет скрытую ёмкость.
Нажатие пустой рукой показывает измеренное напряжение, потери, температуру и защиту.
